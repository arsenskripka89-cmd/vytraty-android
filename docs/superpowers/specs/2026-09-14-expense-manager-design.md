# Vytraty — менеджер витрат для Android з автозахопленням платежів із сповіщень

Дата: 2026-09-14. Статус: затверджено автономно (сесія без зворотного зв'язку), реалізується.

## 1. Мета

Застосунок для обліку особистих витрат, який **сам записує оплати**, зчитуючи сповіщення
Google Pay та банківських застосунків (Monobank, Приват24, Raiffeisen, Revolut). Усе інше —
категорії, гаманці, ручний ввід, історія, діаграми, планові платежі з нагадуваннями,
бюджети — робиться за зразком Wallet by BudgetBakers, але без хмари й підписки.

Ключова відмінність: користувач нічого не вписує руками після оплати. Транзакція
з'являється в історії з позначкою «зі сповіщення», з карткою, з якої списано, і з індикатором
«категорія не призначена». Після першого призначення категорії магазину (мерчанту) застосунок
запам'ятовує пару «мерчант → категорія» і далі призначає її автоматично.

## 2. Обсяг (що входить у першу версію)

1. **Захоплення сповіщень** — `NotificationListenerService`, парсери для Google Pay (Google Wallet),
   Monobank, Приват24, Raiffeisen (MyRaif), Revolut, плюс загальний (fallback) парсер «сума + валюта».
2. **Транзакції** — витрата / дохід / переказ між гаманцями; поля: сума, валюта, дата, гаманець,
   категорія (nullable), мерчант, нотатка, джерело (MANUAL / NOTIFICATION / BANK_API), останні 4 цифри картки.
3. **Категорії** — дерево з двох рівнів не потрібне; плоский список з іконкою, кольором і типом
   (витрата / дохід). Стартовий набір ~18 категорій українською.
4. **Мерчант → категорія** — таблиця правил; оновлюється при ручному призначенні категорії
   транзакції зі сповіщення; застосовується до нових сповіщень і (за бажанням) до всіх
   старих некатегоризованих транзакцій того самого мерчанта.
5. **Гаманці** — назва, тип (готівка / картка / банківський рахунок), валюта, початковий баланс,
   колір, останні 4 цифри картки (для зіставлення зі сповіщенням), банк.
   Баланс рахується з транзакцій. Сповіщення без відомої картки йде в «гаманець за замовчуванням».
6. **Історія** — список по днях із фільтрами (період, гаманець, категорія, лише некатегоризовані),
   бейджі «зі сповіщення», «•••• 1234», «без категорії». Тап — редагування.
7. **Аналітика** — кругова діаграма витрат за категоріями, стовпчики витрат/доходів по місяцях
   (або днях у межах місяця), лінія балансу. Малюємо на Compose `Canvas`, без зовнішніх бібліотек.
8. **Планові платежі** — назва, сума, категорія, гаманець, дата наступного платежу, повторення
   (одноразово / щотижня / щомісяця / щороку), нагадування за N днів. `AlarmManager` +
   `BroadcastReceiver` показує сповіщення; з нього можна одним тапом «Записати» транзакцію.
9. **Бюджети** — ліміт на категорію (або на всі витрати) на місяць; прогрес-бар; сповіщення при 80 % і 100 %.
10. **Інтеграція з Monobank** — особистий API (`api.monobank.ua`, токен користувача):
    імпорт рахунків як гаманців і виписки як транзакцій (джерело BANK_API), дедуплікація за
    `id` виписки. Синхронізація вручну + WorkManager раз на годину.
11. **Інші банки (Приват, Raiffeisen, Revolut)** — тільки через сповіщення. Публічного
    особистого API з простою авторизацією у них немає; для них закладено інтерфейс `BankConnector`,
    щоб додати пізніше без переробки.
12. **Налаштування** — доступ до сповіщень, гаманець за замовчуванням для сповіщень, токен Monobank,
    тестер парсера (вставити текст сповіщення — побачити результат), журнал захоплених сповіщень,
    експорт CSV.

Поза обсягом v1: хмарна синхронізація, кілька користувачів, курси валют онлайн (курс вводиться
руками в гаманці), сканування чеків.

## 3. Технології

- Kotlin 2.0, Jetpack Compose (Material 3), Navigation Compose, Room (KSP), DataStore,
  WorkManager, Retrofit + kotlinx.serialization (Monobank), AlarmManager.
- minSdk 26, targetSdk 35. Без Hilt — ручний `AppContainer` (менше магії, швидша збірка).
- Архітектура: `ui` (екрани + ViewModel) → `domain` (use-cases: парсинг, автокатегоризація,
  баланс) → `data` (Room, DataStore, Monobank API). Односпрямований потік: `Flow` з Room у
  `StateFlow` у ViewModel.

## 4. Модель даних (Room)

- `wallets(id, name, type, currency, initialBalance, color, cardLast4?, bankCode?, monoAccountId?, isDefault, archived)`
- `categories(id, name, icon, color, kind[EXPENSE|INCOME], sortOrder, isSystem)`
- `transactions(id, walletId, categoryId?, kind[EXPENSE|INCOME|TRANSFER], amountMinor, currency,
  timestamp, merchant?, note?, source[MANUAL|NOTIFICATION|BANK_API], cardLast4?, transferToWalletId?,
  externalId? (унікальний разом із source), notificationLogId?)`
- `merchant_rules(id, merchantNormalized UNIQUE, categoryId, hits, updatedAt)`
- `planned_payments(id, title, amountMinor, currency, categoryId?, walletId, kind, nextDueAt,
  recurrence[NONE|WEEKLY|MONTHLY|YEARLY], remindDaysBefore, active)`
- `budgets(id, categoryId?, monthKey "YYYY-MM" | null для щомісячного шаблону, limitMinor, currency)`
- `notification_log(id, packageName, title, text, postedAt, parsed(boolean), transactionId?)`

Суми зберігаються в мінорних одиницях (копійках) як Long.

## 5. Потік захоплення сповіщення

1. `PaymentNotificationListener.onNotificationPosted` → фільтр за package name (список підтримуваних +
   увімкнені користувачем) → витягти `title`, `text`, `bigText`.
2. `NotificationParserRegistry.parse(pkg, title, text)` → перший парсер, що повернув `ParsedPayment
   (amountMinor, currency, merchant, cardLast4, kind, occurredAt)`. Дедуп: однаковий текст протягом 90 с ігнорується.
3. `RecordParsedPaymentUseCase`: гаманець за `cardLast4` або за замовчуванням; категорія за
   `merchant_rules` (нормалізація: нижній регістр, прибрати цифри/зайві пробіли/«ФОП», «ТОВ»);
   вставити транзакцію `source=NOTIFICATION`; записати в `notification_log`.
4. Якщо категорію не знайдено — показати власне тихе сповіщення «Нова витрата 250 ₴ у Сільпо — обрати
   категорію», тап відкриває екран транзакції.
5. Користувач обирає категорію → `AssignCategoryUseCase` оновлює транзакцію, upsert у
   `merchant_rules`, пропонує застосувати до інших некатегоризованих транзакцій цього мерчанта.

Парсери — прості регулярні вирази на повідомленнях українською/англійською; тестуються юніт-тестами
на реальних зразках текстів. Невпізнані сповіщення від підтримуваних пакетів усе одно лягають у
`notification_log` з `parsed=false`, щоб можна було додати шаблон.

## 6. Екрани

Нижня навігація: **Огляд** (баланси гаманців, витрати місяця, останні транзакції, бюджети),
**Історія**, **Аналітика**, **Плани** (планові платежі + бюджети), **Ще** (гаманці, категорії,
банки, налаштування). FAB «+» — ручний ввід.

## 7. Обробка помилок

- Немає доступу до сповіщень → банер на Огляді з кнопкою в системні налаштування.
- Парсер не впізнав → лог, без транзакції, лічильник «невпізнаних» у налаштуваннях.
- Monobank 429/401 → показати в екрані банку, не падати; повтор за годину.
- Видалення категорії → транзакції отримують `categoryId = null`, правила мерчантів видаляються.

## 8. Тестування

- JUnit: парсери (Google Pay UA/EN, Monobank, Приват24, Raiffeisen, Revolut, fallback),
  нормалізація мерчанта, розрахунок балансів, наступна дата планового платежу.
- Збірка `assembleDebug` у CI-подібному режимі локально; ручна перевірка на пристрої — за користувачем.
